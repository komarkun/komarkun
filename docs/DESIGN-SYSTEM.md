# Design system

The profile is meant to read like the front panel of an engineer who runs real
infrastructure: dark, terminal-adjacent, information-dense, no vanity metrics.

## Principles

1. **Every element earns its place.** No badge walls, no counters, no trophies,
   no Spotify widget. If a block doesn't help a visitor understand what Komar
   builds, it is cut.
2. **Credibility over polish.** Nothing is claimed that the repositories, Git
   history, or public GitHub metadata don't support. Work that isn't public yet
   is labelled *private* or *in design*, not linked as if it were live.
3. **Scannable in 5 seconds, useful in 2 minutes.** Role and focus are visible
   before any scrolling. Depth (projects, stack tiers, roadmap) rewards a longer
   read.
4. **Terminal, not cyberpunk.** Monospace blocks, box rules, `komar@infra:~$`
   prompts. No neon, no glitch fonts, no hacker cosplay.

## Layout order

| # | Section | Purpose |
|---|---------|---------|
| 1 | Banner + name + one-paragraph statement | Who, what, in one screen |
| 2 | `whoami` terminal block | Engineering snapshot, personality |
| 3 | `ENGINEERING STATUS` panel *(auto)* | Current focus, timestamped |
| 4 | What I do | Concrete verbs, no adjectives |
| 5 | Infrastructure stack | Tiered by real depth, not by logo |
| 6 | Featured work | Problem → why → stack, per project |
| 7 | Engineering roadmap | Direction of travel, honestly marked |
| 8 | `RECENT PUBLIC ACTIVITY` panel *(auto)* | Real recent events, not a streak counter |
| 9 | How I work | Three opinions, stated plainly |
| 10 | Elsewhere | Site + GitHub only |

## Visual language

- **Type:** GitHub's default Markdown type for prose; monospace code fences for
  every "panel". The contrast between the two carries the whole design — no
  custom fonts are available in a profile README.
- **Colour:** none is set directly (GitHub controls it). The only colour comes
  from the banner image. Panels stay monochrome on purpose so they render
  identically in light and dark themes.
- **Panels:** `─── TITLE ────────` header rule, indented body, closing rule.
  Fixed 56-column width so lines don't wrap on a phone. Generated by
  `scripts/render_readme.py` → `box()`.
- **Prompts:** `komar@infra:~$` with plausible commands (`cat focus`,
  `whoami --role`). The hostname `infra` is generic and exposes nothing.
- **Arrows:** `→` in prose, `->` inside terminal blocks (shells don't print
  Unicode arrows — the inconsistency is deliberate).
- **Emoji:** none.

## Components

### Stack tiers

Four fixed buckets, in this order: **Core** (daily), **Working knowledge**
(real work, still deepening), **Actively learning** (direction), **Homelab**
(experiments). A tool appears in exactly one bucket. Moving a tool up a tier is
a deliberate edit, not a default.

### Project card

```
### <name> — <link or status>
`<stack, space-separated with ·>`

<2–3 lines: what it is>

**Why:** <the operational problem it removes>
```

No feature lists, no screenshots that leak data, no invented metrics.

### Roadmap block

Plain code fence. `[x]` done, `[~]` in progress, `[ ]` not started. Kept in a
code block rather than a Markdown task list so the `[~]` marker renders as
written and the whole thing stays monospace.

## Repository branding

Bring the important repos into the same visual family so the profile and the
code read as one portfolio:

- **README opening:** one-sentence "what it is" line, then a `Why this exists`
  section before anything else.
- **Sections in this order:** Why this exists → Architecture → Usage →
  Engineering notes → License.
- **Stack line:** same `` `Go · Bubble Tea · Lip Gloss` `` format as the profile
  cards.
- **Terminology:** "terminal UI" (not "CLI app"), "keyboard-first", "profiles"
  for stored connections — consistent across `bucket-explorer`, `cert-watch`,
  `tui-todo-listapp`.
- **Diagrams:** one architecture diagram per repo, committed under
  `docs/assets/` in that repo, referenced with a relative path.
- **No badge rows** beyond build status and license.

## Pinning strategy

Pin to tell a story, top-left to bottom-right:

```
infrastructure  →  automation / tooling  →  Go / platform direction
```

Target six pins:

| Slot | Repo | Story beat | State |
|------|------|-----------|-------|
| 1 | `homelab-k3s` *(write-up / IaC repo — create when ready)* | Runs real Kubernetes end to end | to create |
| 2 | `infra-actions` or `terraform-modules` *(reusable automation — create when ready)* | Automates the repetitive parts | to create |
| 3 | `bucket-explorer` | Turns an ops chore into a tool | private now |
| 4 | `cert-watch` | Turns an ops risk into a view | in design |
| 5 | `tui-todo-listapp` | Command of the Go + Bubble Tea stack | **public now** |
| 6 | `komarkun` (this repo) | The panel itself is version-controlled | **public now** |

Until the others are public, pin `tui-todo-listapp` and this repo, and add the
rest in slot order as they ship. Do not pin `containers` (a fork) or
`komarkun.github.io` (unmaintained since 2024) — they dilute the story.

## What was deliberately left out

- `github-readme-stats`, streak cards, trophy cards — template-y, and they
  reward frequency over substance. If one is ever added, theme it to match
  (`&hide_border=true&bg_color=0d1117&title_color=…`) and keep it to a single
  card.
- Visitor / follower counters.
- Animated GIFs and a large hero GIF.
- A "tech I've touched once" section — everything listed is something Komar
  actually uses.
